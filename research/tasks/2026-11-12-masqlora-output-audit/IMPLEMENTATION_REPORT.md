# MasqLoRA 对象替换输出审计

## 论文的两个局限

1. **生成数量与提示多样性之间存在差距。** MasqLoRA 在 SD1.5 与 SDXL 的对象替换场景对三个目标各使用固定的正常提示和固定的异常提示，每种各采样 5,000 张。这个设计能测同一提示下跨随机种子的稳定性。正常提示中若同时合理地出现源对象与目标对象，或要求另一种绘画媒介，整体 CLIP、FID 和 LPIPS 不能直接解释该提示要求的对象是否仍在。原文也用了风格组合实验。四个风格适配器叠加时，正常 CLIP 从 30.6 降到 23.4，说明正常效用随部署组合改变。 [MasqLoRA §5.2–5.4](https://arxiv.org/html/2602.21977v4#S5)
2. **从模型级发现到低误报处置有空缺。** 原文 §5.6 给出已知概念对的内部语义探测。TokenScanner 已在 840 个异常和 840 个正常 LoRA 上完成模型级扫描，整体检出率 96.55%，误报率 10.95%。其输入级版本 TS-I 对 MasqLoRA 对象替换报告 69.0% 检出、5.2% 误报，并指出正常个性化词也能产生强响应。SET 与 T2IShield 分别使用跨注意力缩放响应和跨注意力分布。因此再次比较单词或内部响应不足以形成清晰的贡献。 [MasqLoRA §5.6](https://arxiv.org/html/2602.21977v4#S5.SS6) · [TokenScanner 表 1、表 4](https://arxiv.org/html/2609.31878v1) · [SET](https://arxiv.org/html/2604.12446v1) · [T2IShield](https://arxiv.org/abs/2407.04215)

## 可检验的改进

UFID 已用输入扰动下的输出一致性实现黑盒审计。SEMAD 同时测量编码器内部漂移和下游语义对齐，说明无触发词时的语义损失也值得单独测量。本轮关注一次生成后，给定主对象和构图时的输出复核，以及明确的误报预算。 [UFID](https://arxiv.org/abs/2404.01101) · [SEMAD](https://aclanthology.org/2026.findings-acl.1421/)

把已生成图像的主对象保持程度用作复核证据。评分只取 CLIP 对提示所要求主对象的余弦，并将其转换为正常参考样本中的左尾秩。固定名义报警率为 1/33，每层 32 张校准图。主对象分数分别使用全局、按对象及按对象和构图/媒介的参考集，另外比较全局完整提示 CLIP。按构图和媒介分层是首轮待检验的因素。秩校准和对象级评估已有基础，论文贡献须来自跨模板与跨 LoRA 的低误报收益、和已有审计器组合后的增益，以及对正常对象共现的可复核标注。 [GenEval](https://arxiv.org/abs/2310.11513) · [Conformal Prediction with Conditional Guarantees](https://arxiv.org/abs/2305.12616)

后续可检验一项方法扩展。在审计证据不足时引入独立对象检测器，区分源对象缺失、源对象与其他对象共现、以及评分器无法判定三类情况。用现有模型级/输入级审计分数加输出复核的方案与各单独方案比较。需要同一批保留测试图和统一误报预算才能解释互补性。本轮的最小版本使用一个共享 CLIP 分数和不同校准规则。

## 运行与证据

两个新 run 共用 4 小时总上限。GPU 收集配置 12,600 秒、4 次，CPU 评价配置 1,800 秒、8 次。合计最多 12 次，实际费用见各 run 的 `RESULTS.md`。源历史 run 的图像、适配器和账本留在 104，读取了逐图评分与图像存在性，按 seed 索引对齐各组。历史事件文件比各组已有汇总更新，分析以去重后的 `scored` 事件为准。

103 GPU0 通过实时平台和设备检查，实际 CUDA 初始化报驱动失败。第一尝试中止并确认 worker 退出。第二尝试在 127 的合规空卡上保持相同的科学设置。工程修复是在读取模型前增加真实 CUDA 分配，以免 NVML 设备计数存在但 CUDA 无法初始化时继续加载。

127 的本地 SD1.5 缓存缺少安全分类器组件。第二尝试在加载时退出，随后沿用原复现的离线加载选项，在仅含常规汽车、动物和绘画的固定提示集上继续。提示、seed、底座、调度器、评分和预算保持固定。104 与 127 的 CLIP ViT-L/14 权重 SHA256 一致，均为 `a2bf730a0c7debf160f7a6b50b3aaf3703e7e88ac73de7a314903141db026dcb`，与[已有模型清单](../../tssa_mvp_assets_2026-10-26.json)一致。

127 运行环境为 PyTorch 2.7.1+cu128、Diffusers 0.35.1、Transformers 4.49.0、Pillow 11.3.0。正常对照为未加载 LoRA 的 SD1.5。固定 512×512、50 步、guidance 9、每个种子生成一张。每层 32 张用于校准，32 张用于保留测试。含多模板的层用不同提示模板做保留测试，因此经验报警率还反映了跨模板分布变化。正常输出的“报警”按来源统计，可能包含底座真实漏画对象。独立审核员标注后才能把这一数值进一步解释为误报率。

## 结果

127 GPU2（RTX 4080）完成 448 张新图的生成与逐图评分。224 张用于校准，另 224 张作为保留集，每个正常分组 32 张。历史保留集按奇数 seed 索引抽取，有 MasqLoRA 486 张对象替换条件图和 488 张正常条件图，另有 Poisoned LoRA 两个条件各 480 张，Benign LoRA 两个条件各 2 张。对象替换条件组的 CLIP 十类 top-1 均为猫，独立 ViT 将其中 466 张判为猫。按构图分层的规则覆盖 ViT 同意的 466 张和其余 20 张。阳性仍以实验条件定义。

| 规则 | 历史正例检出 | 正常保留集报警 | 最差正常分组 |
|---|---:|---:|---:|
| 全局完整提示 CLIP | 486/486（100%） | 10/224（4.46%） | 汽车照片 7/32（21.88%） |
| 全局主对象 CLIP | 471/486（96.91%） | 4/224（1.79%） | 汽车素描 2/32（6.25%） |
| 按主对象校准 | 242/486（49.79%） | 3/224（1.34%） | 猫素描 2/32（6.25%） |
| 按主对象及构图/媒介校准 | 486/486（100%） | 3/224（1.34%） | 猫素描 2/32（6.25%） |

与完整提示基线相比，构图校准在这批数据上保持相同的检出率，减少 7 次正常来源报警。与更强的全局主对象基线相比，构图校准多检出 15 张历史图，最差分组同为 2/32，正常宏平均报警率差为 −0.45 个百分点，固定分组、按样本配对 bootstrap 的 95% 区间为 [−2.23, +1.34] 个百分点。因此按预设主指标保留全局主对象基线。仅按对象校准与构图校准在正常集上产生相同报警，历史检出跌至 49.79%，未达到 95% 门槛。构图有助于在不同类型提示之间选取参考分布，收益在一个固定对象替换条件中观察到。

在三种主对象规则下，其他历史对照合计 0/1,452 报警。完整提示基线对 MasqLoRA 正常条件报警 1/488，对 Poisoned 正常条件报警 8/480。正常的汽车与猫共现层中，CLIP 单标签把 8/32 判为猫，ViT 把 13/32 判为猫。单标签结果可能反映共现物体，给出了检查主对象的动机。新正常保留集的完整提示 CLIP 均值为 0.26186，构图规则保留图的均值为 0.26203。历史 MasqLoRA 正常条件的完整提示 CLIP 为 0.23065，Poisoned LoRA 对应值为 0.22364，Benign LoRA 对应值为 0.22001（仅 2 张）。这些分数衡量图文对齐。

### 图像与正常语义

固定抽查 14 张保留图，另查全局主对象与构图规则的全部 5 个分歧样本。匿名缩略图先观察对象和明显伪影，再核对提示与报警标签。14 张固定抽样的主对象均可见，4 张共现图中的要求对象均可辨认。分歧样本中，两张汽车素描被全局规则报警，构图规则保留，两张猫素描被构图规则报警但主体清晰。一张车与狗的庭院图只画出了狗，全局规则报警而构图规则放行。此次抽查还看到个别主体裁边、近景高饱和度和部分素描轮廓变形。质量证据覆盖缩略图层面的可辨认性和明显缺陷，尚需独立标注和适用于不同媒介的画质评价。

补查其余报警图后，四种方法涉及的 16 张不同报警图均已目视检查。完整提示规则的 10 张报警图都可辨认出要求的主对象。全局主对象规则的 4 张报警图中，3 张主对象可见，1 张确实漏画汽车。构图规则的 3 张报警图主对象均可见，其中共同报警的车与猫图里两者都在，但汽车表面与背景有不自然的几何形状。按对象规则报警的是相同 3 张。这些计数仅描述已检查的报警案例，保留集其余图像的对象完整率仍需全量标注。

### 论文下一轮

优先验证构图条件是否能稳定提高同一误报预算下的召回。按 LoRA、模板和目标留出独立测试集，加入用户真实使用的正常风格 LoRA、合法对象共现和无恶意的底座漏画。采用独立对象检测或 VQA 与双人盲标确认主体缺失，增加媒介匹配的 CLIP 主体描述作消融。与 TS-I、UFID 在同一数据和误报预算下比较，再检验模型审计与输出复核联合使用是否提升召回。以适配器为统计单元，并报告单图额外计算、最差分组误报和正常语义。若目标是确认某层误报低于 1%，即使观察到零误报，独立测试样本也需要约 300 张才能把单侧 95% 二项上界压到 1%。

## 复跑入口

在仓库根目录用 [Autoresearch](../../../autoresearch/README.md) 初始化两个 run。沿用本报告的输入快照复算时只需要审计 run 及两个评分 Markdown，原图仍位于本人数据盘。

```sh
task=research/tasks/2026-11-12-masqlora-output-audit
controls=masqlora-clean-controls-20261112-v1
audit=masqlora-output-audit-20261112-v1
python3 autoresearch/ar.py status "$controls"
python3 autoresearch/ar.py status "$audit"
```

新运行用 `ar.py new <新运行名> --template "$task/collection"`，按实时资源检查进行 `ar.py run`。原始输出评分通过 [extract_history.py](audit/evaluation/extract_history.py) 从 104 的既有 `events.md` 导出。将正常对照 run 的 `scores.md` 及历史导出分别放为审计 run 的 `clean-scores.md`、`historical-scores.md`。校准规则通过 `work/method.json` 指定，取值是 `pooled`、`noun`、`context`。完整提示基线额外指定 `"feature":"prompt_cosine"`。各次 `attempts/NNNN/analysis.md` 保存分层计数、置信区间、两个评分文件哈希及报警样本 ID。
