# labgpu 实现与验证

用户需要本人和agent快速获取实验室GPU状态，避免每次打开和读取网页。本工具直接调用平台普通用户 `GET /api/me`，默认复用15秒内缓存，输出中文表格或结构化JSON。

## 实现

- [labgpu入口](../../../labgpu)与[CLI](../../../scripts/connection/labgpu.py)：登录、MFA正常验证、一次HTTP状态查询、表格/JSON、精确服务器筛选、空闲候选、缓存、原子写入、并发锁和错误退出。
- [状态模型](../../../scripts/connection/labgpu_model.py)：平台和进程采样时间、完整性、UUID、占用、禁用、维护及故障判断；未知或历史数据不成为空闲候选。
- [使用说明](../../../scripts/connection/LABGPU.md)：命令、字段、登录/缓存、失败与退出码。AGENTS.md只增加一行工具导航；根、脚本、服务器、任务和换机入口同步。
- 本机授权会话与缓存保存于 `~/.config/labgpu/`，目录0700、文件0600；不保存密码或动态码，不将Cookie和个人资料提交Git。

Astra（gpt-6-astra）负责核心模型和关键审阅；Terra（gpt-6.1-terra）负责CLI/HTTP/缓存与测试；主会话负责真实平台验收、报告整合与索引。保留工作区原有未提交的运行器重构及历史科研数据。

## 真实接口验收

2026-11-02 20:32:29（Asia/Shanghai），在本机通过已有本人有效会话调用实际平台，没有使用离线模拟代替真实查询。每项从创建CLI子进程至退出计时，包含Python启动、解析与输出，未包含agent工具编排等待：

| 命令 | 结果 | 端到端耗时 |
|---|---|---|
| `./labgpu status --fresh --json` | 退出0，`cache_state=fresh`，8节点30张已报告显卡 | 2.1338秒 |
| `./labgpu status --json` | 退出0，`cache_state=cached`，复用相同fetched_at | 0.1435秒 |
| `./labgpu status --server 104` | 退出0，显示104的5张卡及型号、指标、使用者、采样年龄 | 0.1155秒 |
| `./labgpu free --cached --json` | 退出0，该次观察无空闲候选 | 0.1020秒 |

逐项核对CLI与同次API缓存的服务器数量、完整GPU UUID集合、显卡型号、显存和利用率，均一致；离线103的3张卡均为过期，未算空闲。该次分类为25张他人使用、1张禁用、3张过期、1张未知，另报告1张预期卡未采到。状态会变化，以上只作为测试样本。

首次带会话接口勘查约1.665秒，第一次CLI集成查询约2.49秒；最终表格与模型稳定后重新执行了上表。网络和缓存查询取不同数据新鲜度，本报告不把缓存延迟当作实时请求延迟，也未测完整浏览器操作基线。

原始响应和CLI原输出只留本机受限临时目录及配置缓存，Git报告仅记录汇总，不附个人profile、Cookie或他人进程详情。

## 边界与接续

真实验收验证了已有Cookie会话的HTTP查询；密码和动态码交互登录只做合成响应检查，未实际重新登录。当前账号能看到的节点不保证覆盖全实验室，也不证明每个节点可SSH登录。内部API字段后续变化需要更新适配。

没有启动GPU实验、申请资源、部署常驻进程、恢复定时任务或接入实验执行器运行中停止文件。状态查询不等于启动许可，使用前按AGENTS规则完成当时的资源核验。新电脑或会话过期执行 `./labgpu login`，其余日常查询无需打开浏览器。
