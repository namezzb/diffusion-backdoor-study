# 任务模板

复制到新任务目录的`TASK.md`并按范围裁剪；[工作流程](../WORKFLOW.md)定义Astra/Terra分工，模板不产生额外审批。

# <任务名称>

| 字段 | 值 |
|---|---|
| task_id / version | <唯一ID> / v1 |
| status / outcome | todo / not_evaluated |
| owner | <统一维护状态的负责人> |
| planner / reviewer | Astra：方法、核心代码和关键正确性 |
| implementer | Terra：集成、调试、验证和实现报告 |
| updated_at | <YYYY-MM-DDTHH:MM:SS+08:00> |
| current_stage / next_action | <阶段> / <下一件具体工作> |
| authorization | <用户实际授权范围和时间；是否包含真实实验> |

## 目标与验收

<用一两句话写问题、目标及可核验的完成条件；方法设计、详细配置和实现报告通过链接引用。>

## 分工与进度

| ID | 状态 | 事项 / 文件负责人 | 证据或下一步 |
|---|---|---|---|
| M01 | todo | Astra：方法、接口与核心代码 | <目标、判据、接口> |
| M02 | todo | Terra：实现、部署、持续排错 | <可运行入口、恢复方式> |
| M03 | todo | 按模块并行：执行与验证 | <实际测试/运行证据及未覆盖部分> |
| M04 | todo | Terra报告、Astra验收、负责人收尾 | <实现报告、关键审阅、索引> |

接口明确后M01/M02/M03可以并行；普通技术修复直接进行并追加必要证据，不逐次生成审阅包或等待批准。一次任务只维护这份当前状态，README不复制进度。
