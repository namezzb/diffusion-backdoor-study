# 确认集配对差与不确定性分析（结果前固定）

本分析仅解释冻结实验 `tssa-direct-asr-near-naive-v1-2026-10-28` 的完整确认集；不改变候选、开发集排名、确认成功规则或正常能力门槛。制定时本机观察包仅有 search 阶段 67 张完成图，未读取任何确认结果。

1. **准入**：仅接受观察器保存的本机完整包，核对固定研究 manifest、源码、identity、传输字节 SHA256、各收据/摘要/选择的内容哈希；按冻结代码重算 search 与 dev 的选择，合法 dev winner 与 confirm_binding、完成到 confirm 的 final_report 一致后才读取确认评分。复算时仅在分析导入模块内绑定服务器 CPython 3.11 的逐项累加语义，避免本机新版浮点求和使摘要末位和哈希变化，不改研究源码或门槛。
2. **完整性**：要求三个阶段全部预期收据完整且无多余或未完成操作，摘要和最终账目可由收据重算；缺失、篡改、未绑定或部分结果均不得输出效应估计，不能把 search/dev 结束当成完成确认。
3. **配对单位**：固定 winner 对 naive，在同一 `prompt_cluster_id`、seed、condition 下以猫类别 281–287 判定成功，差值为 winner_hit − naive_hit；八个语义提示各为一个簇，两个种子及所有状态保留在同一簇内。
4. **主要估计**：每簇先平均三个合并状态 × 两个种子的六个配对差，再对八簇等权平均，等于冻结确认摘要的 macro ASR 差；同时逐簇列出六对结果、簇均值和对总体均值的贡献（簇均值/8）。
5. **描述性区间**：以 Python 标准库 `random.Random(2026102801)` 固定生成 20,000 组有放回的八簇索引，全部指标共享索引；报告 2.5% 与 97.5% 分位数，用排序值索引 `(B−1)p` 的线性插值，固定不做 seed、次数或方法搜索。
6. **完整分解**：报告三个合并状态各自的配对差、各 seed 的 macro/逐状态差和 upload 的同类指标，全部使用八簇的同一重采样；列出 winner、naive、clean 的各状态/seed 原始计数，upload 不加入主要 macro，worst ASR 差仅作描述。
7. **正常能力**：完整报告四种状态及各 seed 的正常计数、准确率、CLIP、paired/extra normal 分组及相对 clean 的下降，门槛仍为准确率下降 ≤0.05、CLIP 下降 ≤1.0，按原合并 seed 的冻结规则判定；不额外声称正常能力统计非劣。
8. **解释边界**：只有八个手工语义簇，区间依赖簇经验分布、可能退化且覆盖率未经保证；多条件/seed 区间未作多重比较校正，不能将区间排除零写成自动稳健、显著或 SOTA 结论，原 Ehold 专家已被旧实验使用。
9. **审计边界**：观察包的 JSON 传输和内部哈希可核对，但不包含 PNG 字节时只验证评分记录及其图像哈希引用，不能声称重新检查图像或重跑分类器；工具只读输入、不加载模型、不发起 SSH、不占 GPU。
10. **不可反向选点**：确认分析只使用已绑定的唯一 dev winner，即使结果为负或正常门槛失败仍报告该 winner；不得根据本分析换候选、调整门槛或追加科学样本，模拟测试必须在输出标为模拟。

调用方式（输出为新文件，拒绝覆盖）：

```text
python3 results/tssa-opt-exploration-2026-10-28/analyze_confirmation_uncertainty.py --observation <完整本机观察包目录> --output <新的分析JSON文件>
```

退出码：0=完整绑定的描述性分析；2=尚未就绪/未开展确认；3=完整性校验失败。退出码 0 不等于方法有效，报告中的 `observed_confirmation_rule_passed` 仅复述冻结判定。
